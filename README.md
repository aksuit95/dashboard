# 개인용 한국 주식 리서치 대시보드

한국 정규장 마감 이후에도 해외 프록시(ADR, GDR, 선물, 미국 ETF, DEX 무기한선물)로 한국 주식의 방향을 보고, 수급·기업 재무까지 한 화면에서 확인하는 **개인 연구용** 대시보드입니다.

화면 구성은 [Jusikbot](https://jusikbot.com/)의 공개 페이지를 참고했습니다. 이 저장소는 Jusikbot과 무관하며, 그들의 코드·상표·데이터를 복제하지 않습니다. 시세와 통계는 각자 이용 가능한 공개 출처에서 수집하고, 화면의 숫자 정의는 아래 계산식을 따릅니다.

표시되는 모든 수치는 정보 제공용입니다. 투자 권유나 매매 신호가 아닙니다.

## 한국시장 공통 기준: KRX 15:30 종가

코스피200 공매도 분석은 `/short-selling`에서 확인합니다. 운영 데이터가 없는 동안 합성 샘플을 선택할 수 있습니다. 수집기·JSON 스키마·실호출 검증 결과와 실행 방법은 [공매도 문서](docs/short-selling.md)를 참고하세요.

**모든 한국시장 분석의 기본 가격·시간 기준은 한국시간(KST, Asia/Seoul) 오후 3시 30분의 KRX 정규장 종가입니다.** 국내 종목·지수·섹터의 종가, 일간 및 기간별 등락률, 이동평균, 상대강도, 국내 기준가격을 사용하는 비교 계산에 공통 적용합니다. 최신 가격과 과거 비교 가격 모두 같은 KRX 정규장 종가 기준을 사용합니다.

- NXT 저녁 20:00 종가, 시간외 가격, 거래소가 구분되지 않는 통합 종가를 KRX 종가 대신 사용하지 않습니다. 데이터 소스의 필드와 실제 값을 확인합니다.
- 장중에는 직전 완료 거래일의 KRX 종가를 사용합니다. 주말·휴장일 조회도 직전 거래일로 해석하고 실제 기준일을 표시합니다.
- 16:00 이후 수집·갱신은 데이터 반영을 기다리는 운영 시각입니다. 분석 기준 가격의 시각은 15:30이며, 화면에는 **기준일·거래소·기준 시각**과 **수집 시각**을 구분합니다.
- KRX 종가가 없으면 결측 또는 수집 실패로 처리합니다. 다른 거래소 가격으로 대체하거나 기존 통합 종가 캐시를 KRX 값으로 표시하지 않습니다.
- 실시간·NXT·시간외·야간선물·해외 프록시를 명시적으로 다루는 화면은 해당 시장의 시세와 세션을 별도 표시합니다. 그 화면에서도 국내 주식의 일별 기준가격은 KRX 15:30 종가입니다. 공시 등 발표 자료는 원본 발표일·시각을 유지합니다.

이 항목은 프로젝트 공통 규칙입니다. 개별 기능 설명의 일반적인 ‘종가’·‘정규장 종가’는 이 기준을 뜻합니다. 새 기능과 기존 기능 수정에도 적용하며, 세부 수집 코드가 이 규칙을 충족하는지는 기능별 검증이 필요합니다. 개발 작업 지침은 [AGENTS.md](AGENTS.md)에도 명시합니다.

## 이 대시보드가 답하는 질문

- 정규장이 끝난 뒤 삼성전자·SK하이닉스는 해외에서 어떻게 움직이고 있는가.
- ADR·GDR 가격을 보통주 1주 기준으로 환산하면 KRX 대비 프리미엄이 얼마인가.

### Global Proxy (`/`)

정규장 종료 뒤에도 한국 주식의 해외 가격을 카드로 보여 줍니다. 각 카드는 이름, 심볼, 거래소, 장 상태(Live / Closed), 원화 환산 가격, 대비, 등락률을 표시합니다.

- **ADR.** SK하이닉스 나스닥 ADR(`SKHY`). 1 ADS = 보통주 1/10. 화면 가격은 보통주 1주 기준 원화이고, 같은 시각 KRX 종가 대비 프리미엄을 함께 표시합니다.
- **DEX 무기한선물 (Hyperliquid).** `xyz:SMSN`, `xyz:SKHX`, `xyz:SKHY`, `xyz:HYUNDAI`, `xyz:KR200`. 기준은 직전 KRX 정규장 종가 대비 24시간 변화. 8시간 펀딩비는 포지션 쏠림을 읽는 보조 지표입니다. ADR 퍼프는 KRX 퍼프 대비 프리미엄도 표시합니다.
- **글로벌 선물.** KOSPI200 야간선물([PreKOSPI](https://www.prekospi.com/methodology)의 한국투자증권 야간 체결 수집 기록), 주간선물(네이버 FUT, 20분 지연), Nasdaq 100 선물, S&P 500 선물. 야간 등락은 야간 시가 대비이며 원본 체결 시각·월물·출처를 표시합니다. 야간장 종료 후에는 마지막 야간 기록을 유지하고, 장중 90초 이상 미갱신이면 지연으로 표시합니다. 공개 비공식 API의 실패·스키마 변경 시 야간 시세를 수신 불가로 표시하며 주간 종가로 대체하지 않습니다.
- **매크로.** 미국 10년물 금리, WTI, USD/KRW.
- **GDR.** 삼성전자 런던 GDR(`SMSN.IL`, 1 GDR = 보통주 25주, 1주 환산), SK하이닉스 프랑크푸르트(`HY9H.F`, 1주 환산).
- **미국 ETF 프록시.** Roundhill Memory(`DRAM`), iShares MSCI Korea(`EWY`), iShares Semiconductor(`SOXX`).

삼성전자 보통주·우선주와 하이닉스 ADR 괴리율 종가는 GitHub Actions가 수집·저장하고 Git 배포로 반영합니다. 한국 시세는 거래일 16:00 KST에 KRX Open API와 네이버의 KRX 정규장 15:30 종가 이력을 대조하고, KRX가 미발표거나 접속 실패이면 명시적인 네이버 KRX 정규장 종가만 사용하며, ADR·환율은 07:00 KST에 별도로 수집합니다. 화면은 저장 JSON만 읽으며 각 기준일·수집 시각을 표시합니다. 실패 시 기존 정상 파일을 유지합니다. 자세한 설정은 `docs/vercel-daily-refresh.md`를 참고하세요.

### 시장 지표 장기 비교 (`/adr`)

코스피·코스닥은 KRX 정보데이터시스템의 정규장 15:30 종가, 코스피·코스닥 ADR은 기존 네이버 KRX 정규장 20거래일 수집값을 사용합니다. 원/달러는 Yahoo `KRW=X`의 런던 시간 기준 완료 일봉으로 KRX 종가와 기준 시각이 다릅니다. 지수·환율·ADR은 최대 5년 이력을 제공합니다. ADR 과거는 현재 거래 가능한 종목의 과거 KRX 정규장 종가로 재구성하므로 상장폐지 종목이 빠지고 다른 집계처와 차이가 날 수 있습니다. 화면은 각 지표의 출처·기준일·수집 시각과 이력 시작일을 따로 표시합니다. 나스닥 종합과 S&P 500은 Yahoo 일별 미국 정규장 종가를, 미국 10년물은 미 재무부의 10년 만기 파 수익률(CMT, 뉴욕 약 15:30 호가 기준)을 사용합니다. 2년물도 수집하지만 기본으로 숨깁니다. 미국 자료는 현지 기준일과 수집 시각을 별도 표시합니다.

ADR 5년 재수집은 `npm run adr:export -- --backfill-5y`이며 종목별 요청이 많아 시간이 걸립니다. 새 거래일 수동 갱신은 ADR을 먼저 `npm run adr:export`로 갱신한 다음 `python scripts/market_indicators/collect.py`를 실행합니다. 테스트는 `python -m unittest discover -s scripts/market_indicators -p "test_*.py"`입니다. KRX 웹 수집에 기존 `KRX_ID`와 `KRX_PW`가 필요합니다. 원본별 실패는 기존 정상 파일을 유지하며 실패를 표시합니다. 기준일과 원본 데이터 파일은 `public/data/market-indicators-live/`에 별도로 저장합니다. 코스피·코스닥·나스닥·S&P 500은 기존 검증된 이력을 보존하고 마지막 저장일 이후만 이어서 수집하며, 저장된 이력이 없거나 출처가 맞지 않으면 과거를 자동으로 다시 채우지 않고 실패 처리합니다. 주말과 프로젝트 캘린더에 확인된 휴장일만 직전 값을 사용하고 불명확한 결측은 비웁니다. 현재 휴장일 캘린더는 2026년만 검증되어 이전 연도의 주중 휴장일은 결측으로 남을 수 있습니다. GitHub Actions가 한국 지표와 환율을 평일 16:00 KST에 ADR 수집 직후 갱신하고, 미국 지표는 매일 09:00 KST에 별도로 갱신합니다. 미국 일정은 한국 거래일 캘린더와 독립적으로 동작합니다. 변동이 있을 때만 저장소에 게시해 Vercel 배포를 시작합니다. 일부 수집에 실패하면 다른 정상 결과와 실패 상태를 게시하고 작업을 실패로 표시합니다. 예약 수집에는 GitHub 저장소의 `KRX_ID`, `KRX_PW` 비밀값과 Actions 쓰기 권한이 필요합니다. 한국 거래 캘린더는 다음 연도가 시작되기 전에 갱신해야 합니다.

### 코스피·코스닥 등락비율 (`/adr`)

네이버 시장 목록의 거래 가능 종목과 `regularMarketClosingPrice` KRX 정규장 15:30 종가 이력을 사용해 최근 20거래일 상승 종목 수 합 ÷ 하락 종목 수 합 × 100을 계산합니다. 보합은 비율에 넣지 않습니다. 현재 종목 목록으로 과거를 재구성하므로 과거 상장폐지·편입 변동이 반영되지 않아 다른 제공처와 차이가 날 수 있습니다. 장중과 휴장일에는 직전 완료 거래일을 표시합니다. 수집일과 종가 기준일을 구분하고 실패 시 기존 저장본을 유지합니다. `npm run adr:export`로 수동 수집하며 자동 갱신은 장 마감 후 실행됩니다.

프리미엄과 원화 환산은 장중 환율을 씁니다. 환율이 없으면 마지막 유효 환율을 쓰고, 카드에 기준 시각을 남깁니다.

### Risk Indicators (`/risk`)

변동성, 심리, 매크로를 한 화면에 모읍니다.

- **이격도.** `종가 / N일 이동평균 × 100`. N은 25일 또는 50일입니다. 정의가 출처마다 다르므로 화면에 이 식을 고정해 적습니다.
- **변동성.** VIX, SOX.
- **CNN 공포·탐욕 지수.** 현재 점수(0–100), 전일·1주·1개월·1년 전 비교와 1개월·3개월·6개월·1년·전체 선차트. 매일 오전 10시 KST를 경계로 한 번 수집한 성공값을 공유하며, 최신 점수는 미국 거래일에 반영합니다. 원본 기준 시각과 수집 시각은 KST로 표시합니다. 같은 날 새로고침은 저장값을 읽습니다. 수집 실패 시에는 재시도를 허용합니다.
- **금리.** 미국 장단기 금리차(10년−2년).

CNN 데이터는 `production.dataviz.cnn.io/index/fearandgreed/graphdata/2021-02-01`에서 가져옵니다. 공식 지원 API가 아니며 실행 환경에 따라 자동 요청이 차단될 수 있습니다(HTTP 418 등). 첫 수집이 차단되면 오류와 빈 상태를 표시하며, 예시 데이터를 실제 지수로 표시하지 않습니다. 데이터 출처는 [CNN Fear & Greed Index](https://www.cnn.com/markets/fear-and-greed)입니다.

`vercel.json`의 `0 1 * * *` 예약 작업이 방문자 없이도 `/api/cron/fear-greed`를 호출합니다. Vercel Production 환경 변수에 `CRON_SECRET`을 임의의 긴 비밀값으로 설정하고 재배포해야 합니다. 이 값이 없거나 인증이 다르면 수집 경로는 401을 반환합니다. Vercel Hobby에서는 오전 10–11시 KST 사이에 실행될 수 있습니다. 화면의 첫 요청이 먼저 오면 같은 일별 수집을 수행합니다. CNN 갱신 알림을 구독하는 방식이 아니므로 확인 이후에 CNN 값이 바뀌면 다음 날 반영됩니다.

일별 성공 응답은 Next.js Data Cache에 날짜 키로 저장하여 Vercel 인스턴스 사이에서 공유합니다. 로컬 SQLite는 보조 스냅샷이며, Vercel의 임시 SQLite만으로 예약 수집 결과를 전달하지 않습니다. Data Cache는 영구 보관용 DB가 아니며 캐시가 제거되면 다시 수집합니다. 수집 실패 시 해당 인스턴스에 남은 스냅샷이나 화면의 기존 값을 유지하고, 실패 응답을 하루 동안 고정하지 않습니다.

KOSPI·KOSDAQ 이격도 차트 구간은 6개월, 1년, 3년입니다.

### 수급분석 (`/investor-flow/*`)

사이드바에는 **수급분석** 버튼 하나를 두고, 화면 안에서 코스피·코스닥 시장과 각 종목 수급, 국민연금 공시 탭으로 전환합니다.

- 국민연금 공시는 DART 공시 목록에서 국민연금공단이 제출한 해당 월의 대량보유·임원주요주주 공시를 찾고, 접수번호가 일치하는 지분공시 상세를 표시합니다. 보유수량 증감은 보고된 수치이며 실제 매매를 의미하지 않을 수 있습니다. 정정 공시를 표시하고 상세 미반영은 결측으로 둡니다. `npm run pension:export`로 수집하며 GitHub Actions는 매일 18:30 KST에 한 번 수집하도록 설정합니다. 저장 결과가 바뀔 때만 배포하고 수집 실패 시 이전 결과를 유지합니다. Production 반영에는 코드·데이터 배포와 GitHub `DART_API_KEY`가 필요합니다.

- 시장 화면은 토스증권 Open API가 제공하는 코스피·코스닥 시장 전체의 투자자별 매매대금에서 매수−매도를 계산해 최근 1년의 구간 누적·일별·5·20·60거래일 순매수(억 원)를 표시합니다. 구간 누적 차트는 선택한 차트 구간의 첫 거래일부터 시작하고, 자료 결측 이후는 결측으로 둡니다. 비교 지수는 각각 코스피·코스닥의 KRX 15:30 종가입니다. 외국인은 등록·미등록 외국인 합계입니다. 토스 이력을 페이지별로 조회하고, 해당 거래일의 KRX 지수 종가를 KRX 정보데이터시스템에서 가져옵니다.
- 종목 화면은 코스피·코스닥 각 시장의 시총 상위 10개를 대상으로 순매수 수량, 기간별 누적과 연속 순매수 일수를 표시합니다. 토스 API는 종목별 거래대금을 제공하지 않아 시총 대비 금액 비율은 표시하지 않습니다.
- 수급분석의 시세·시총은 KRX 정보데이터시스템의 정규장 일별 자료를 사용합니다. 시장별 시총 상위 10개 종목의 종가를 네이버 `regularMarketClosingPrice`와 대조하고 불일치하면 수집 실패로 처리합니다. 지수 이력도 KRX 정규장 종가를 사용합니다.
- 토스 조회에는 `TOSS_CLIENT_ID`와 `TOSS_CLIENT_SECRET` (또는 `toss_API_KEY`와 `toss_API_SECRET`), KRX 시세에는 `KRX_ID`와 `KRX_PW`를 서버 환경변수에 설정합니다. 투자자별 수급 자체는 토스 API로 조회합니다.
- 결측 수급은 0으로 바꾸지 않고 합산·누적을 결측 처리합니다. 토스 외국인은 등록외국인 기준입니다. 토스 수급은 KRX·NXT 합산이므로 KRX 15:30 가격과 거래 범위가 다릅니다.

수급분석은 **이 PC의 Windows 작업 스케줄러에서 거래일 16:00 KST 이후 수집**합니다. PC가 켜져 있고 사용자 세션에 로그인되어 있어야 하며, 네트워크·자료 미발표 등 실패 시 1시간 간격으로 실패 화면만 재시도합니다. 성공한 화면은 같은 거래일에 다시 수집하지 않습니다. 화면 진입·탭 전환·저장 자료 새로고침은 배포된 `data/investor-flow/board.json`(로컬 미배포 시 SQLite의 `investor_flow_daily_snapshots`)만 조회하며 토스·KRX 외부 API를 호출하지 않습니다. 가격은 KRX 정규장 **15:30 종가**이며, 원본 수급 갱신 시각과 실제 수집 시각은 별도 표시합니다. 16시에 저장한 토스 수급은 이후 NXT 거래·원본 정정 내용을 당일 추가 반영하지 않습니다.

- `npm run job:investor-flow`로 네 탭을 일괄 수집합니다. `job:daily`·`job:poll`에도 연결했습니다. 16시 전·주말·등록된 휴장일에는 수집하지 않으며 미확인 캘린더는 오류로 보류합니다. `job:poll`이 실행 중이면 16시 이후 첫 확인 때 수집하고, 늦게 시작하면 당일 미실행분을 한 번 수집합니다.
- SQLite `investor_flow_daily_runs`의 거래일 고유 키로 동일 DB의 중복 실행·동시 실행을 차단합니다. 실패·미발표는 기록하며 PC 예약 작업이 1시간 간격으로 실패한 화면을 다시 수집합니다. 수집은 여러 종목·이력 API 요청으로 구성되는 한 번의 배치입니다. 중단된 실행도 당일 자동 재실행하지 않습니다.
- 저장 자료가 없으면 대기 안내를 표시합니다. 다음 거래일 수집이 누락되면 마지막 저장 자료와 실제 기준일을 표시합니다. 새 기준일의 가격을 이전 날짜 가격으로 대체하지 않습니다.
- 이 PC의 `Dashboard Investor Flow` 작업이 평일 16:00부터 1시간 간격으로 실패분을 재시도합니다. 별도 `tmp/investor-flow-runner` 체크아웃에서 수집하고 결과 파일만 GitHub에 커밋·푸시해 Vercel 배포를 유발합니다. 토스는 허용 IP에서만 호출되며 PC의 공인 IP가 바뀌면 허용 IP를 갱신해야 합니다. 성공 후 같은 거래일 중복 수집은 하지 않습니다.
- PC의 `C:\dashboard\.env`에서 KRX 웹 로그인 정보와 토스 키를 읽습니다. 키는 JSON·로그·Git 커밋에 포함하지 않습니다.
- `data/investor-flow/board.json`에 최근 30개 수집일의 스냅샷과 실행 기록을 보존합니다. 실패한 화면의 재시도에서도 성공한 화면은 보존합니다. 동일 거래일 실패 기록을 재시도하려면 `npm run investor-flow:export -- --retry-failed`를 사용합니다.
- 배포 화면은 공통 JSON을 읽으므로 Vercel의 인스턴스별 임시 SQLite에 의존하지 않습니다. `/api/investor-flow`와 `/api/investor-flow/toss`에 파일 추적을 지정했습니다. 별도의 Vercel 수급 cron은 등록하지 않습니다.
- 로컬에서는 영구 SQLite와 상시 `npm run job:poll`을 사용하거나, Windows 작업 스케줄러에서 작업 폴더 `C:\dashboard`로 매일 16:00에 `npm.cmd run job:investor-flow`를 실행합니다. 코드 변경만으로 OS 예약 작업이나 배포 설정이 활성화되지는 않습니다.

### 투자위험 (`/investment-risk`)

관리·거래정지·투자주의·투자경고·투자위험 목록과 코스피200 재무 경고를 종목코드로 연결합니다. 시장경보는 공매도 수집 작업에서 저장한 네이버 목록의 조회 시각 기준이며, 가격은 별도 수집한 KRX 15:30 정규장 종가입니다. 재무 경고는 현금·재무건전성의 공시 자료와 같은 계산식을 사용하고 기업별 결산일을 표시합니다. 기존 경보 파일은 종목명·시장 구분이 없을 수 있으며 다음 수집부터 확보 가능한 정보를 저장합니다. 재무 분석 대상 외 또는 미확보 종목은 안전하다고 해석하지 않습니다.

### 현금·재무건전성 (`/financials`)

코스피200 기업의 공시 현금 잔액, 최근 5개년·TTM FCF와 유동성 비율을 비교합니다. DART 공시 수집 작업은 `npm run financials:export`, 실패 기업 이어받기는 `npm run financials:export -- --retry-failed`입니다. 화면에서는 저장된 공시 실적과 재무제표 원문 계정을 읽습니다. 금융업은 일반기업 평가에서 제외합니다. 주석이 필요한 가용 유동성·총차입금·순현금은 검증 전까지 결측입니다. 기존 QuantiWise FCF는 별도 참고값으로만 표시합니다. [재무 분석 문서](docs/financial-health.md)에 데이터 재사용 범위, 계산식, 실행 방법과 제한 사항을 정리했습니다.

개별종목 밸류에이션과 현금·재무건전성의 시가총액은 평일 16시 GitHub Actions가 KRX 웹 통계에서 수집한 공통 파일을 사용합니다. KRX 정규장 15:30 종가와 상장주식수·시총의 관계를 검증하고 상위 종목의 네이버 정규장 종가와 대조합니다. 시총 갱신과 별개로 재무 공시 및 QuantiWise 엑셀은 수동 수집합니다.

## 권장 구조

개인용이라 배포 없이 로컬에서 돌아가게 설계합니다. 시세는 서버에서만 가져오고, 브라우저는 자체 API만 호출합니다. 키를 클라이언트에 넣지 않습니다.

```text
app/                  Next.js App Router 페이지
components/           시세 카드, 차트, 표, 사이드바
lib/market/           프리미엄·이격도 등 계산 함수
lib/sources/          출처별 수집기 (실패 시 빈 값이 아니라 마지막 스냅샷)
jobs/                 장중 폴링, 일별·월별 배치
data/                 SQLite (시세, 일별 지표, 공시, 수집 로그)
config/universe.ts    심볼, ADR/GDR 배수, ETF 목록, 비교 쌍
```

스택은 Next.js, TypeScript, Tailwind CSS, Node 내장 SQLite(`node:sqlite`), Lightweight Charts입니다. Drizzle과 네이티브 SQLite 모듈은 쓰지 않습니다. Node 24에서 추가 빌드 없이 로컬 파일을 열기 위해서입니다. 작업 스케줄은 `npm run job:poll` 또는 Windows 작업 스케줄러로 충분합니다.

## 실행

```text
npm install
copy .env.example .env
npm test
npm run job:ingest
npm run job:backfill
npm run dev
```

Vercel에 올리면 함수 디스크가 읽기 전용이라 SQLite는 `/tmp`에 둡니다. 인스턴스가 새로 뜨면 시세는 비어 있고, 수집 상태 화면에서 다시 받으면 그 인스턴스에만 남습니다. Node.js 24가 필요합니다. `node:sqlite`는 그 버전부터 플래그 없이 동작합니다.


수집 주기의 출발점:

| 데이터 | 주기 | 비고 |
| --- | --- | --- |
| Hyperliquid 퍼프, 미국 선물·ETF·환율 | 15–30초 | 장중에만. 휴장에는 마지막 호가 유지 |
| KRX 현재가·종가 | 정규장 1분, 그 외 종가 1회 | 프리미엄의 분모 |
| DART | 10–15분 | 시총 필터 후 저장 |

외부 호출이 실패해도 마지막 성공 시각의 값을 보여 주고, 카드에 `stale`을 표시합니다. 0이나 빈 차트으로 덮어쓰지 않습니다.

## 계산

환율은 USD/KRW 미드(또는 사용하는 피드의 종가) 하나입니다. 모든 원화 환산이 이 값을 공유합니다.

```text
보통주 1주 원화 = 해외 표시가격 × 그 통화의 원화 환율 / 증권 1장이 나타내는 보통주 수
프리미엄(%)   = (비교 가격 / 기준 가격 − 1) × 100
```

`SKHY`는 1 ADS = 보통주 1/10이므로 나눗수는 0.1입니다. 10으로 나누면 1주 가격이 실제보다 100배 작아집니다. 삼성 런던 GDR은 1장 = 보통주 25주입니다. 배수는 `config/universe.ts`에만 두고 화면 코드에 하드코딩하지 않습니다. 법인행동(분할·배수 변경)이 있으면 적용일과 함께 기록합니다.

이격도는 종가를 이동평균으로 나누어 계산합니다. 결측값은 결측으로 유지합니다.

## 마크 미너비니 기술적분석 (`/minervini`)

사이드바의 **마크 미너비니 기술적분석**에서 코스피200과 그 아래 코스닥150을 추세 → RS → VCP 근사 → 거래량 돌파 순으로 확인합니다. 상위 시총 종목이나 ETF 보유종목으로 대체하지 않고 네이버의 현재 지수 구성 전체를 페이지별로 받습니다. 기업 분할 등에 따라 일시적으로 정원보다 많을 수 있습니다. 영문자가 포함된 신규 종목코드도 지원합니다.

- 추세는 50·150·200일 단순이동평균, 200일선 21거래일 연속 상승, 252거래일 고저가를 사용합니다. 105거래일 상승·20일선은 보조 정보입니다.
- RS는 `0.4×63일 + 0.2×126일 + 0.2×189일 + 0.2×252일 수익률`의 해당 지수 내 백분위입니다. 코스피200과 코스닥150을 섞지 않고, 각 지수에서 253개 종가가 있는 전체 구성종목으로 먼저 순위를 계산한 후 유동성·추세 필터를 적용합니다. 동점은 평균 순위를 부여하며 표시 반올림 전 값으로 RS 70·80·90 필터를 판정합니다. IBD 공식 RS와는 다릅니다.
- VCP는 전일까지 30일을 10일씩 나눈 3구간 고저폭의 연속 축소, 마지막 폭 10% 이내, 일중 변동폭 축소, 10일 평균 거래량 < 50일 평균을 조합합니다. 스윙 기반 실제 VCP의 근사이며 차트 확인이 필요합니다.
- 피벗은 **당일을 제외한 20일 최고가**, 돌파 거래량은 **당일을 제외한 50일 평균 대비 1.5배 이상**입니다. 추세·RS·VCP 통과와 피벗 ±5%를 셋업으로 보고, 종가 돌파+거래량을 충족하면 돌파로 표시합니다. 추세·RS 통과 후 피벗 대비 5%를 초과하면 추격 주의입니다.
- 시총 1,000억원, 20일 평균 종가×거래량 근사 10억원을 하한으로 둡니다. 우선주·거래 제한·상태 미확인·당일 거래량 0·이력 부족은 제외 이유를 표시합니다. 관리종목·정리매매 지정은 별도 KRX 원장과 대조하지 않았습니다. 현재 구성·시총·거래 상태를 사용하므로 과거 편입 시점 재현이나 백테스트가 아닙니다. EPS·매출 성장(SEPA), 섹터 RS·지수 초과수익은 포함하지 않습니다.
- 손절 참고가는 `max(피벗×0.92, 마지막 10일 저점×0.995)`입니다. 표에는 피벗에서 손절 참고가까지의 거리를, 상세에는 종가 기준 손절 거리와 2R 참고가를 제공합니다. 호가단위·슬리피지·갭·수수료는 반영하지 않습니다.

미너비니는 `lib/sources/krx-daily-prices.ts`의 KRX 정규장 일별 시세를 최대 360거래일 수집합니다. 네이버 `daily-prices/paged`의 `openingPrice`·`highPrice`·`lowPrice`·`tradingVolume`과 **`regularMarketClosingPrice`(KRX 15:30 종가)**를 사용합니다. 기존 `fchart` 피드와 시간외 값이 포함될 수 있는 `closingPrice`는 계산에 사용하지 않습니다. 이동평균·RS·추세·VCP·피벗·거래량·위험 참고값 모두 이 일봉으로 다시 계산합니다. 공급자 시세에 배당·분할 보정을 별도로 추가하지 않습니다. 각 지수 전체 구성의 일봉이 같은 기준일까지 반영되어야 새 스냅샷을 저장합니다. 일부 실패·종가 미반영은 해당 지수의 마지막 KRX 성공 결과를 보존하며 실패를 해당 일의 성공으로 캐시하지 않습니다. 이력이 253거래일보다 짧은 신규주는 정상 수집으로 집계하되 RS·후보에서 제외합니다. 전체 목록이 코스피200 190~210개, 코스닥150 140~160개 범위를 벗어나거나 중복 페이지가 있으면 자동 갱신을 보류하므로 대규모 지수 변경 시 `config/minervini.ts`의 검증 규칙을 갱신해야 합니다.

스냅샷 버전 4와 `priceBasis: KRX_REGULAR_CLOSE`를 기록하고 배포 캐시 키도 교체했습니다. 이전 기준의 미너비니 저장값은 동일 날짜여도 재수집하며, 실패 시 이전 통합 종가 결과를 KRX 화면에 표시하지 않습니다.

두 분석 영역은 각각 검색·정렬·필터·새로고침·상세 이용 안내를 제공합니다. `/api/minervini?universe=kospi200` 또는 `universe=kosdaq150`은 배포된 `data/minervini/board.json`을 읽으며 방문자 요청으로 외부 시세를 수집하지 않습니다. 지수별로 최신 성공 결과를 보존합니다.

### 매일 장 마감 후 갱신

한국시간 **16:00**을 일별 경계로 사용합니다. 가격은 KRX 정규장 **15:30 종가**이며, 주말·휴장일과 16:00 전에는 직전 완료 거래일을 사용합니다. 특별 운영시간 미확인일·미등록 연도는 수집을 보류합니다.

- GitHub Actions `.github/workflows/sector-daily.yml`에서 섹터와 함께 평일 **16:00 KST**에 `npm run minervini:export`를 실행하고, `data/minervini/board.json`의 변경을 커밋하여 Vercel Git 배포를 시작합니다. GitHub 예약과 배포는 지연될 수 있습니다. 별도의 Vercel 미너비니 cron은 사용하지 않습니다.
- 두 지수는 각각 검증합니다. 한 지수 수집이 실패하면 해당 지수의 이전 정상 결과를 유지하고 다른 지수의 성공 결과를 배포합니다. 실패한 경우 Actions 실행은 실패로 표시되며, 재실행하면 같은 날짜에 성공한 지수는 재수집하지 않고 실패한 지수만 수집합니다.
- 화면을 열 때 배포된 일별 결과를 읽고 유지합니다. 수집이나 배포가 지연되면 직전 결과와 기준일·지연을 표시합니다. 배포 결과가 없으면 수집 대기 상태를 표시합니다.
- `npm run minervini:export`는 로컬에서 배포 파일을 수집할 때 사용합니다. 기존 `job:minervini`, `job:daily`, `job:poll`은 별도 로컬 SQLite 수집용이며 배포 파일을 갱신하지 않습니다.

### 코스피200 밸류에이션 (`/valuation`)

왼쪽 사이드바의 **밸류에이션 → 코스피200 밸류에이션**에서 QuantiWise `IKS200` 조회표의 선행 PER·PBR·EPS·BPS·EV/EBITDA·영업이익·FCF 중 실제 제공되는 항목을 선차트로 봅니다. 지표 선택, 1개월~5년/전체 기간, 마우스 날짜·값 확인, 선택 기간 평균선을 지원합니다. 영업이익·FCF의 `Local thou`는 천원에서 억원으로 환산합니다. 주가 지수와 EPS의 단위가 다를 수 있어 지수/EPS로 PER를 만들어내지 않습니다.

- **원본 파일 설정:** `.env.local`에 `VALUATION_WORKBOOK_PATH=C:/경로/코스피200.xlsx`를 설정합니다. 이 경로는 로컬 내보내기 명령만 사용하며 Vercel 환경 변수에 설정할 필요가 없습니다. 엑셀 원본과 `.env.local`은 커밋하지 않습니다.
- **수동 갱신:** QuantiWise에서 Refresh를 완료하고 **Ctrl+S로 저장**한 다음, `C:/dashboard`에서 `npm run valuation:export`를 실행합니다. 다른 파일을 지정하려면 `npm run valuation:export -- "C:/경로/코스피200.xlsx"`를 사용합니다. 명령은 엑셀을 직접 실행하거나 새로고침하지 않습니다.
- **생성 파일:** `data/valuation/kospi200.json`에 차트 수치, 지표 코드·단위, 원본 저장 시각, 내보내기 시각을 저장합니다. 로컬 `/valuation`에서 **데이터 반영**을 눌러 이 JSON을 확인합니다. 원본 파일이 변경되지 않았으면 다시 실행해도 JSON과 내보내기 시각을 바꾸지 않습니다.
- **Vercel 반영:** 검증한 JSON을 코드와 함께 커밋·푸시합니다. Vercel이 연결된 Production 브랜치를 배포하면 `/api/valuation`은 빌드에 포함된 JSON을 읽습니다. 방문자가 페이지를 새로 열거나 **데이터 반영**을 누르면 해당 배포의 데이터를 봅니다. 주기적 확인, 브라우저 파일 연결, PC 경로 접근, 별도 DB는 사용하지 않습니다. Git 연동과 자동 Production 배포는 Vercel 프로젝트에 설정돼 있어야 합니다. 현재 코드는 이 연동 설정 자체를 변경하거나 자동으로 커밋·푸시하지 않습니다.
- **원본 검증:** QuantiWise의 Code/Item Code/Unit/DATE 행을 읽고 `IKS200`만 사용합니다. 날짜 없는 잔여 행과 결측·오류값을 제외합니다. 지표별 실제 날짜를 사용하고 서로 다른 시트의 행 위치를 맞춰 붙이지 않습니다. 동일 지표가 여러 시트에 있으면 유효 관측값이 가장 많은 시트를 선택하며, 같은 날짜 값이 다르면 화면에 경고합니다. 파일 읽기 실패 시 마지막 정상 차트를 유지합니다. 엑셀 원본은 수정하지 않습니다.

내보내기는 검증 완료 후 임시 파일을 원자적으로 교체합니다. 손상된 XLSX, 검증 경고, 읽는 동안 변경된 파일, 기존 지표 누락, 최신 날짜 역행은 오류로 종료하고 이전 JSON을 보존합니다. 원본 시트 간 값 불일치가 있다면 엑셀을 수정·저장한 뒤 다시 실행합니다.

최초 기능 배포 때는 사이드바·페이지·API·내보내기 코드·의존성과 JSON을 함께 커밋해야 합니다. 이후 데이터만 갱신할 때는 아래처럼 JSON만 커밋하면 됩니다. `git diff`로 지표와 날짜를 먼저 확인합니다.

```powershell
npm run valuation:export
git diff -- data/valuation/kospi200.json
git add data/valuation/kospi200.json
git commit -m "Update KOSPI 200 valuation data"
git push
```

Git에 포함된 JSON은 해당 저장소 및 배포 사이트의 접근 권한에 따라 노출됩니다. 원본 엑셀의 다른 시트나 로컬 전체 경로는 JSON에 포함하지 않습니다.

### 개별종목 밸류에이션 (`/valuation/stocks`)

밸류에이션 메뉴의 **개별종목 밸류에이션**에서 같은 엑셀의 `종목별 밸류에이션` Peer Analysis 시트를 봅니다. 종목명·코드 검색, 지표별 정렬(결측은 마지막), PER 양수 필터와 종목 선택을 지원합니다. PER·PBR·EV/EBITDA, 지배/전체 EPS·BPS, 영업이익·FCF를 원본 항목 코드로 구분하며 천원 단위 금액은 억원으로 바꿉니다. 0·음수는 보존하고 결측은 `—`로 표시합니다.

종목을 선택하면 TradingView Lightweight Charts™의 주가 차트와 `KRX:종목코드` 원본 링크가 함께 바뀝니다. 기본 위젯에서 삼성전자 KRX 심볼의 외부 표시가 제한되는 것을 확인했으므로, 차트 라이브러리에 미너비니와 같은 KRX 전용 일봉 수집기를 연결합니다([TradingView 위젯 데이터 안내](https://www.tradingview.com/widget-docs/faq/data/)). **KRX 15:30 정규장 종가**와 일별 시가·고가·저가·거래량을 사용하며 장중 미완료 봉과 NXT·시간외 종가는 제외합니다. 장중·주말에는 직전 완료 거래일, 16:00 이후에는 새 완료 거래일을 기준으로 합니다. 주가·거래량, 기간 선택, 마우스 OHLC 확인을 지원하며 QuantiWise 수치를 외부에 전송하지 않습니다. 일봉 API는 내보낸 종목 목록만 허용하고 최대 1,500일봉을 5분 캐시합니다. 캐시 키와 클라이언트 조회 URL을 KRX 기준으로 바꾸어 기존 일봉 캐시와 구분하며 응답에 `asOf`·`priceBasis`·`fetchedAt`를 포함합니다. 일봉 실패 시 재시도와 원본 차트 링크를 제공합니다. 원본 엑셀은 종목별 현재 스냅샷이므로 밸류에이션 과거 차트는 만들지 않습니다. 구성일, QuantiWise 갱신 시각, 원본 항목 기준일(`CPD-1TD`: 조회일의 직전 거래일)을 표시합니다.

QuantiWise Refresh 후 저장하고 `npm run valuation:stocks:export`를 실행하면 `data/valuation/stocks.json`을 생성합니다. 기존 `VALUATION_WORKBOOK_PATH`를 사용하며 별도 파일은 `STOCK_VALUATION_WORKBOOK_PATH` 또는 명령의 파일 경로 인자로 지정합니다. 지수 갱신은 기존 `npm run valuation:export`를 그대로 사용합니다. 개별종목 내보내기는 파일 변경·단위 오류·중복 종목·기존 지표 누락·구성일 역행·동일 구성일 종목 누락 시 기존 JSON을 보존합니다. 이후 JSON과 코드를 배포하고 화면의 **데이터 반영**을 누릅니다.

### 섹터별 등락률 (`/valuation/sectors`)

밸류에이션 사이드바의 **섹터별 등락률**에서 코스피200·코스닥150을 전환하고, 섹터 카드를 선택해 해당 종목을 확인합니다. 일간 / 1W / 1M / 3M / 6M / 1Y 선택, 종목명·코드 검색, 기간별 오름·내림차순 정렬과 네이버 종목 차트 링크를 제공합니다. 종목 표에는 여섯 기간이 동시에 표시됩니다.

우측 상단 **날짜별 보기**에서 마지막 완료 거래일부터 최근 30일 중 원하는 날짜를 선택합니다. 날짜를 바꾸면 일간으로 전환하고 선택일을 끝점으로 여섯 기간을 다시 계산합니다. 주말·휴장일은 직전 거래일로 해석하며 선택일과 실제 기준일이 다른 이유를 화면에 표시합니다. `/api/valuation/sectors?universe=kospi200&date=2026-11-01`처럼 조회하며 잘못된 날짜·미래일·범위 밖 요청은 400입니다. 지수·거래일별 성공 결과를 SQLite와 배포 캐시에 저장하고, 과거일 수집 실패 시 다른 날짜의 결과로 대체하지 않습니다. 기존에 저장된 해당 거래일 스냅샷을 우선 사용하고, 최초 과거 조회는 현재 수집한 구성종목·섹터로 과거 가격을 비교하므로 당시 편입·편출을 재현하는 백테스트는 아닙니다.

- 표시 가격과 기간별 비교 가격은 모두 **KRX 정규장 15:30 종가**입니다. 네이버 일별 시세 `stockSecurity/items/v2/domestic/{code}/daily-prices/paged`의 `regularMarketClosingPrice`를 사용하고, NXT가 포함될 수 있는 `closingPrice`나 기존 `fchart` 종가는 사용하지 않습니다. 최신 완료 거래일과 1 / 5 / 21 / 63 / 126 / 252거래일 전 KRX 종가를 비교합니다. 배당은 포함하지 않으며 이력이 짧은 기간은 `—`로 표시합니다. 장중 수익률이 아닙니다.
- 섹터 값은 해당 지수의 현재 구성종목 중 유효 수익률의 단순평균이며 공식 섹터 지수와는 다릅니다. 각 카드에 전체·산정 종목 수를 함께 표시합니다. 상승은 빨강, 하락은 파랑입니다.
- 네이버 전체 업종 목록과 종목별 업종을 `config/sectors.ts`의 20개 리서치용 섹터로 묶습니다. 반도체장비와 일부 미용·2차전지·원전·지주 종목은 코드별 분류가 우선입니다. 신규 편입·사업 변경 때 분류를 검토하고, 분류/계산 방식 변경 시 `lib/sources/sector-returns.ts`의 `sectorSnapshotVersion`을 올려 저장값과 배포 캐시를 갱신합니다. 공식 KRX 분류·테마 구성과 동일하지 않으며 미지원 업종은 기타/미분류에 남깁니다.
- `/api/valuation/sectors?universe=kospi200` 또는 `universe=kosdaq150`로 조회합니다. 기존 미너비니와 같은 구성종목 전체 검증, 16:00 KST 거래일 경계·휴장 캘린더를 재사용합니다. 섹터용 KRX 전용 시세는 100개씩 필요한 과거 253개 종가를 수집하며 날짜 중복·페이지 잘림·정규장 종가 누락·기준일 미반영을 거절합니다. 실패 시 해당 지수의 마지막 KRX 정상 결과를 보존하며 1분 뒤 재시도합니다. 스냅샷의 `priceBasis: KRX_REGULAR_CLOSE`와 버전 4로 이전 통합 종가 저장값·캐시를 교체하며, 기존 통합 종가 결과를 KRX 화면의 대체값으로 노출하지 않습니다. 미너비니·개별종목 밸류에이션 차트도 같은 KRX 일별 시세 수집기를 사용합니다.
- SQLite `sector_return_snapshots`와 Next.js 거래일별 캐시를 사용합니다. 첫 방문·화면 새로고침은 미수집일만 수집합니다. 화면의 1분 폴링은 하지 않습니다. 최신 날짜를 보고 있을 때만 거래일 16:00 KST에 한 번 갱신하고, 백그라운드·절전 상태였다면 복귀 시 누락된 갱신을 한 번 수행합니다. 과거 날짜 화면은 자동 갱신하지 않습니다. 첫 방문·지수/날짜 변경·수동 새로고침 시에는 선택한 결과를 조회합니다. 수집 실패 후 화면이 주기적으로 재시도하지 않으며 수동 새로고침으로 재시도할 수 있습니다. `npm run job:sectors`로 두 지수를 초기 적재하며 `job:daily`·`job:poll`에도 연결했습니다. Vercel `/api/cron/sectors`는 UTC 07:00(한국시간 16:00)이며 `CRON_SECRET` Bearer 인증이 필요합니다. 배포 및 OS 예약 작업은 별도이며 Vercel 캐시·임시 SQLite의 보존 한계는 미너비니와 같습니다.

### 미국 섹터 등락률

`섹터별 등락률`의 미국 시장은 제3자 집계 S&P 500 구성종목과 NASDAQ 100 구성종목을 티커 기준으로 합칩니다. NASDAQ 전체 상장 종목을 뜻하지 않으며, 복수 주식 클래스는 각각 포함됩니다. 구성과 업종은 수집 시점 기준입니다. 원본 업종을 리서치용으로 재분류하며 공식 섹터 지수가 아닙니다. Yahoo Finance의 미국 정규장 일봉 종가를 사용하고, SPY 거래일을 기준으로 1·5·21·63·126·252거래일 전 가격과 비교합니다. 배당은 제외하고 가격 누락은 결측 처리합니다. 미국 거래일과 수집 시각을 별도로 표시합니다.

`.github/workflows/us-sector-daily.yml`이 한국시간 화~토 오전 6시 10분에 수집을 시작하고 `data/us-sectors/board.json`을 배포합니다. GitHub Actions 예약 실행은 지연될 수 있습니다. 공휴일에는 마지막 완료 거래일을 사용합니다. 90% 미만의 최신 종가 수집 시 기존 배포 파일을 유지합니다. 수동 수집: `python scripts/us-sectors/collect.py`. 외부 원본과 네트워크가 필요합니다.
