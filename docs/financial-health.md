# 코스피200 현금·재무건전성

페이지 `/financials`, 조회 API `/api/financials`, 사이드바 **종목 분석 → 현금·재무건전성**.

## 단계별 구현과 기존 자료 점검

| 단계 | 구현 | 데이터 처리 |
| --- | --- | --- |
| 1. 기존 자료 점검 | SQLite·밸류에이션·섹터·구성종목 검사 | 기존 DB에는 현금 잔액·전체 CF 이력이 없음. 공시 목록은 재무제표가 아님 |
| 2. 수집 연결 | DART 고유번호 ZIP, 기업개황, 전체 재무제표 / KRX 일별매매 API | 현금·BS·손익·CF를 새로 수집. 연결 우선, 명시적 데이터 없음(013)일 때만 별도 조회 |
| 3. 분석·비교 | 연간·TTM·단일 분기 FCF, 유동성 비율, 경고, 비교 정렬·필터 | 누적 CF 차감, 결측·금융업 분리. 단위는 저장 원, 화면 억원 |
| 4. 공시 계정·근거 | 최신 보고서의 재무상태표·현금흐름표·손익계산서 원문 계정과 금액 | 공시 원문, 기간, 통화를 확인할 수 있으며 예상 현금을 계산하지 않음 |
| 5. 검증 | 계정·기간·수치·시나리오·보안 테스트, 빌드, 브라우저 점검 | DART 공시 접수번호, 매핑한 원문 계정과 사용 필드 추적 |

### 재사용하는 기존 데이터

- `data/valuation/stocks.json`: QuantiWise `E124260.M` FCF를 원으로 환산해 **공급자 참고값**으로만 상세에 표시. 기존 파일은 금액 단위가 억원이다. 선행 조회표의 구성일·원본 갱신일을 보존하며, 상세 정의·예상기간이 검증되지 않아 공시 FCF·전망 계산과 혼합하지 않는다.
- `data/sectors/board.json`: 기존 업종명을 재사용한다. 일반기업 평가 가능 여부는 DART 기업개황의 업종코드와 함께 확인한다. 업종 미확인은 평가를 보류한다.
- 지주회사 코드 `64992`만으로 금융업으로 분류하지 않는다. 같은 코드라도 NAVER 업종이 은행·증권 등인 금융 지주와 석유·조선·복합기업 등 산업 지주를 나눈다. 업종이 없으면 분류를 보류한다.
- 기존 NAVER 구성종목 수집 함수를 재사용하되 수집 실행 시 전체 페이지를 새로 확인한다. 현재 구성종목이지 과거 시점 구성종목이 아니다. 기업행위에 따라 정확히 200개가 아닐 수 있다.
- 시총은 평일 16시 수집한 KRX 웹 통계의 공통 저장 파일을 사용한다. 종가·상장주식수·시총 관계와 상위 종목의 네이버 정규장 종가를 검증한다.

## 수집과 운영

재무 수집에는 `DART_API_KEY`, 시총 수집에는 KRX 웹 로그인 `KRX_ID`, `KRX_PW`가 필요하다. 인증 정보는 저장 JSON·브라우저·오류 메시지에 넣지 않는다. Node 24의 ZIP 해제·CRC 검증을 사용한다.

```powershell
# 최초 전체 수집 / 캐시를 재사용한 이어받기
npm run financials:export

# 미완료·오류 기업만 재시도
npm run financials:export -- --retry-failed

# 먼저 일부 실패 기업만 확인
npm run financials:export -- --retry-failed --limit=4

# 지정 기업 수집
npm run financials:export -- --codes=005930,000660,015760,105560

# 정정공시·계정 갱신을 강제로 확인
npm run financials:export -- --refresh

# 외부 요청 없이 저장한 기업개황으로 업종 분류만 재계산
npm run financials:export -- --reclassify
```

화면 조회는 저장된 JSON만 읽는다. 시총은 평일 16시 GitHub Actions가 수집·배포하며 실패 시 이전 정상 파일과 실제 기준일을 표시한다. 재무 공시는 별도의 수동 수집을 실행할 때 갱신된다.

수집은 4개 기업씩 처리하고 DART 요청 시작 간격을 최소 400ms로 제한한다. 네트워크 오류·429·5xx는 최대 3회 시도한다. 회사별 오류는 기록하고 기존 보고서를 보존한다. 4개 기업 처리마다 전체 구성에 대한 체크포인트를 원자 교체한다. Windows 파일 잠금은 짧게 재시도하며 기존 파일을 먼저 삭제하지 않는다. 미완료·오류가 남으면 작업 종료 코드는 1이다.

- 배포 자료: `data/financials/board.json`
- 로컬 작업 캐시: `tmp/financial-cache-v1/` (Git 제외)
- 기업개황·고유번호: 7일, 최근 재무보고서: 1일, 오래된 보고서: 30일 캐시. 정상적인 데이터 없음도 같은 기간 캐시한다.
- 최근 5개 사업연도 연간 보고서, 당기와 전기 1·2·3분기 보고서 중 이미 종료된 기간을 조회한다. 아직 미공시된 보고서를 합성하지 않는다.
- 12월 결산 외 기업은 회계기간을 잘못 맞추지 않도록 수집을 보류한다.

## 계산 기준

`lib/financials/parse.ts`에서 재무제표 구분과 표준 XBRL ID를 먼저 확인하고, 없으면 정확한 한국어 계정명으로 매핑한다. 부분 문자열만으로 현금·차입금을 분류하지 않는다. 중복 계정의 금액이 상충하면 결측으로 처리한다.

- FCF = 영업현금흐름 − 유형자산 취득 − 무형자산 취득. 취득 지출은 절댓값으로 정규화한다. 기업 인수대금은 별도다.
- CF의 `thstrm_amount`는 누적 값이다. 손익의 분·반기 `thstrm_amount`는 3개월 값이므로 `thstrm_add_amount`만 누적 실적으로 사용한다. 누적 필드가 없으면 결측이다.
- TTM = 전년 연간 + 당기 누적 − 전년 동기 누적. 같은 연결·별도 범위의 보고서 3개가 모두 필요하다.
- 단일 분기 = 당기 누적 − 직전 분기 누적. Q1은 그대로 사용한다. Q4는 연간 − Q3 누적이다.
- 3년 평균은 최근 **연속 3개 연도**의 같은 범위 FCF가 모두 확보됐을 때만 표시한다.
- 유동비율 = 유동자산 / 유동부채, 당좌비율 = (유동자산 − 재고) / 유동부채.
- FCF 수익률 = TTM FCF / KRX 기준일 시가총액. 비율의 분모가 0·음수이면 해석 제한으로 결측이다.
- 현금 조정 검증: CF 기초 현금 + 영업·투자·재무현금흐름 + 환율효과와 CF 기말 현금을 대조한다. 기타 변동 때문에 차이가 나면 원문 확인 신호를 표시한다. BS 현금과 CF 기말도 비교한다.

금융업에는 일반기업 FCF 순위·유동성 비율·전망을 적용하지 않는다. BIS·CET1·LCR·K-ICS 등 업권별 지표는 현재 연결 데이터가 없어 원문 확인 사항으로 남긴다.

## 가격·공시 시점

- KRX 웹 통계의 `TDD_CLSPRC`, `LIST_SHRS`, `MKTCAP`을 검증해 사용한다. 가격 기준은 **KRX 정규장 15:30 KST**, 실제 수집 시각은 별도 필드다.
- 16시 전·주말·휴장일은 기존 검증된 거래일 캘린더로 직전 완료 거래일을 선택한다. 자료 미발표·실패이면 해당 작업의 가격은 결측이다. NXT·통합 시세나 이전 가격으로 해당 기준일을 채우지 않는다.
- 보고서별 재무기간·연결/별도·접수번호·공시일·수집 시각을 보존한다. 공시일은 접수번호의 날짜이며 원본 API에 공시 시각이 없어 시각은 만들지 않는다.
- 현재 API가 반환한 정정 보고서는 재수집 시 반영한다. 캐시 유효기간 중에는 이전 공시일·수집 시각이 그대로 표시된다. 정정 이력의 과거 버전을 복원하는 백테스트 기능은 제공하지 않는다.

## 공시 원문 계정 보강

`npm run financials:export -- --enrich`는 저장된 각 기업의 최신 보고서에 대해 DART 전체 재무제표를 다시 조회한다. 회사·연도·범위·접수번호가 일치할 때만 재무상태표, 현금흐름표, 손익계산서 원문 계정을 보존한다. 기존 보고서와 접수번호가 다르면 덮어쓰지 않고 전체 재수집이 필요하다. BS는 결산일 잔액, CF와 분·반기 손익은 누적 금액을 표시한다. 원문 계정은 상위와 하위 계정이 함께 나타날 수 있으므로 중복 합산하지 않는다. 사용자 가정에 기반한 현금 전망은 제공하지 않는다.

## 남는 데이터 제한

- DART 전체 재무제표 API는 주석 전체를 제공하지 않는다. 사용제한 현금, 단기상품 환금성, 주석 내 차입·리스와 정확한 만기 스케줄은 확인되지 않아 **가용 유동성·총차입금·순현금·순차입금/EBITDA를 확정하지 않는다**.
- 대신 식별한 차입 항목만 `표기 차입금`으로 표시한다. 이를 순현금 기업 수·안전 점수에 사용하지 않는다. 단기 상환 참고 지표도 전체 만기 금액이 아님을 표시한다.
- 현금과 예치금을 합친 금융업 계정을 현금및현금성자산으로 오인하지 않는다. 정확한 매핑이 없으면 현금 열은 결측이다.
- 모든 CAPEX·배당·자사주 항목이 명시되는 것은 아니다. 미표기 항목을 거래 없음으로 간주하지 않는다.
- 컨센서스·공식 가이던스·정량적 일회성 조정 데이터는 확보되지 않았다.
- 최초 실수집 도중 DART 연결 초기화가 발생해 일부 기업만 확보될 수 있다. 화면의 커버리지·기업별 오류·실제 재무기간을 확인하고 네트워크 회복 후 `--retry-failed`로 보완한다.
