# Vercel 일별 자동 갱신

Production 배포 후 Vercel Cron이 방문자 없이도 아래 API를 호출합니다.
각 API와 화면은 같은 날짜 키의 Next.js Data Cache를 사용합니다.
성공한 날짜의 결과는 재사용하며, 시세를 갱신할 때마다 재배포할 필요가 없습니다.

| 항목 | 한국시간 | UTC cron | API |
| --- | --- | --- | --- |
| 미국 ADR 종가 | 오전 7시 | `0 22 * * *` | `/api/cron/proxy-close/us` |
| 삼성전자·하이닉스 한국 종가 | 오후 4시 | `0 7 * * *` | `/api/cron/proxy-close/kr` |
| 미너비니 분석 | 오후 4시 | `0 7 * * *` | `/api/cron/minervini` |
| 공포·탐욕 지수 | 오전 10시 | `0 1 * * *` | `/api/cron/fear-greed` |

미국 오전 7시 작업의 UTC 날짜는 한국 날짜보다 하루 전입니다.
미국 가격은 오전 7시 이전에는 직전 갱신분을 유지합니다.
한국·미국 종가 화면은 각 갱신 경계에 다시 조회하며, 1분 주기 조회는 하지 않습니다.
화면이 닫혀 있어도 cron이 수집하고, 다음 방문에서 저장된 결과를 읽습니다.
예약 작업보다 화면 요청이 먼저 들어오면 같은 날짜 결과를 먼저 수집할 수 있습니다.

## 최초 배포 설정

1. Vercel 프로젝트의 Production 환경 변수에 `CRON_SECRET`을 긴 임의 값으로 설정합니다.
   기존 공포·탐욕/미너비니 작업에 설정된 값이 있으면 그대로 사용합니다.
2. 이 변경을 Production에 배포합니다. Preview 배포에서는 cron이 실행되지 않습니다.
3. Vercel 프로젝트의 Cron Jobs에서 위 네 경로와 일정을 확인합니다.
4. 각 작업의 실행 로그와 API의 `ok`, 기준일을 확인합니다. 인증 없는 호출은 401입니다.

Vercel Hobby의 일별 작업은 지정한 시각부터 한 시간 안에 실행될 수 있습니다.
정각 실행은 보장하지 않습니다. 더 정밀한 일정이 필요하면 Vercel Pro 또는 외부
스케줄러에서 동일한 API를 Bearer 인증으로 호출하도록 설정합니다.
공식 제한: https://vercel.com/docs/cron-jobs/usage-and-pricing

Data Cache는 영구 저장소나 분산 잠금이 아닙니다. 캐시 삭제나 동시 최초 요청 시
추가 수집이 일어날 수 있습니다. 원천 데이터 반영이 늦거나 수집이 실패하면
정해진 시각에 새 값이 표시되는 것을 보장할 수 없습니다.
엑셀/QuantiWise 밸류에이션과 20초 주기 시세는 이 예약 설정에 포함하지 않습니다.
